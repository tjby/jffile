## 1. 数据与方法

1. `tools/scan-upload.sh` 在服务器上只读扫描，产出：
   - `upload-files.tsv`：类型 / 大小 / mtime / 相对路径；
   - `upload-inventory.md`：扩展名分布、顶层条目汇总、目录树、样本。
2. `tools/probe_parse.py` 在本地按「将要实现」的规则模拟解析 203 个条目，
   输出分类、片名/年份/季/集猜测、置信度和风险标记。
3. `tools/sub_stats.py` 单独统计字幕配对、标签、压缩包和附件。

> 这一步的目的不是写代码，而是**用真实数据验证规则**，避免在 200 个条目上拍脑袋。

## 2. 环境事实（会直接影响设计）

| # | 事实 | 证据 | 影响 |
| --- | --- | --- | --- |
| 1 | 目标机 Python **3.10.12** | `python3 -V` | 原计划 3.12+ 不成立；`tomllib` 是 3.11+ 才有 |
| 2 | **没有 pip**，`python3 -m venv` 也建不出（`ensurepip` 缺失） | `No module named pip` / `ensurepip is not available` | 只能是**纯标准库**程序，不能装任何第三方包 |
| 3 | `ffprobe`、`mediainfo`、`7z` 都没有，只有 `unzip` | `command -v` | 读不了时长/编码；`.7z`/`.rar` 解不开 |
| 4 | `/data` 只剩 **9.6 GB**（99% 满） | `df -h` | 只能 `move`（同盘瞬时完成）；`copy` 会直接爆盘 |
| 5 | 库目录已有 **默认 ACL：`user:jellyfin:rwx`** | `getfacl /data/jellyfin/movies` | 新建文件自动对 jellyfin 可读，**不需要 chown、不需要 root** |
| 6 | Jellyfin 库路径已确认 | `/var/lib/jellyfin/root/default/*/options.xml` | `电影 → /data/jellyfin/movies`，`节目-剧集 → /data/jellyfin/tvshows` |
| 7 | **`EnableRealtimeMonitor = true`** | 同上 | Jellyfin 本来就会实时监控文件变化，调 API 刷新只是「加保险」 |
| 8 | TMDb / TVDB / Bangumi 全部不通，只有 PyPI、GitHub raw、豆瓣页面能连 | `curl` 探测 | 联网补年份这条路基本断了（豆瓣可爬但不稳定，不建议） |

**结论：程序应当是「Python 3.10 + 纯标准库 + 配置文件用 JSON + 只做 move + 不 chown」的形态。**
这些和之前需求文档里的假设有出入，我会在讨论后统一改 `doc/requirements.md`。

### 3.2 命名风格（决定解析难度）

### 3.3 字幕实况（很关键）

| 事实 | 数量 | 影响 |
| --- | ---: | --- |
| 有外挂字幕的视频 | **78 / 1297（6%）** | 绝大多数动画是**内封字幕**，外挂是少数 |
| 其中**同时有简繁两份**的视频 | **76** | 「单份字幕」规则几乎用不上，**多份才是常态** |
| 字幕标签 | `tc` 70、`sc` 69、`chi` 26、`chs` 7 | 全是非标准语言码 |
| 字幕放在**单独子目录**（和视频不同目录） | 12 | 如 `1-12 sup/*.sup`，Jellyfin 不会去子目录找，必须搬过去 |
| 压缩包内含字幕/字体 | **24 个包**（`Subtitles.7z`、`1-12 sup.zip`…） | 不解压 = 这些剧在 Jellyfin 里就是没字幕 |
| 孤儿字幕 | 13 | 12 个是上一条的 `.sup`，1 个是缺集（视频没上传） |

已验证 Jellyfin 源码（`MediaInfoResolver.GetExternalFiles` + `ExternalPathParser` + `NamingOptions`，2026-11 的 master）：

- **只扫描视频所在目录**，不递归子目录 → 字幕必须搬到视频旁边；
- 匹配规则：字幕主名必须以**视频主名**开头，且紧跟的字符必须是 **`.`**（`MediaFlagDelimiters = ['.']`，只有点）。
  所以 `片名 (2023).sc.ass` 能识别；`片名 (2023)_sc.ass`、`片名 (2023) - sc.ass` **不能**；
- 语言段不认识时**不会丢弃**，而是当作字幕标题（`Title = "sc"`、`Language = null`）→ 字幕照样能用，只是语言未知；
- 支持的扩展名：`.ass .mks .sami .smi .srt .ssa .sub .sup .vtt`；
  **`.idx` 单独按 VobSub 配对处理**，**`.ttml` / `.dfxp` 根本不在列表里**（本库没有这两种，忽略即可）；
- `forced` / `foreign` / `default` / `sdh` / `cc` 会被解析成播放标志（`片名 (2023).forced.srt`）。

### 4.4 问题标记中文对照（现在报告里就是「代码（中文名）」）

> 数量来自 `real-run/20261119-181151-preview.json`。**一个条目可以同时有多个标记**；
> 标记为 0 的也列出来，方便你知道程序会检查这件事。

**你问的 `EP_RANGE_SUSPECT` =「集号范围异常」**，判定规则只有两条：
**① 识别出的最小集号 > 1**（说明只传了后半段，比如从第 5 集开始），
**② 最大集号 > 60**（通常是跨季连续编号，比如史莱姆第三季接着第二季的 48 往下排）。
程序**不会自己改集号**：只按识别出的数字排序，例如 `04.mp4` `05.mp4` `06.mp4` 就存成 `S01E04` `S01E05` `S01E06`，不重编号、也不补 01–03。`EP_RANGE_SUSPECT` 只是报告里的提醒，不阻止入库。本库 14 个条目命中，绝大多数属于第 ① 种：
`DEAD DEAD DEMONS…`（5–17）、`欢迎来到日本，妖精小姐。`（2–12）、
`Tsuma, Shougakusei ni Naru`（3–12）、`迷宫饭`（4–…）等；
真正的第 ② 种只有 `Tensei Shitara Slime Datta Ken 3rd Season [48.5-72]`（S03E48–72，另有半集）。

| 代码 | 中文名 | 这是什么情况 | 条数 | 要不要你处理 |
| --- | --- | --- | ---: | --- |
| `NO_YEAR` | 缺少年份 | 目录名和文件名里找不到 `19xx`/`20xx`，目标名**不带** `(年份)`，不会瞎编 | 34 | 一般不用；重名片可事后在 Jellyfin 里 Identify |
| `SEASON_ASSUMED_1` | 未标季号，按第 1 季 | 没有 `S02` / `2nd Season` / `第三季` 任何线索，只能按 S01 入库 | 73 | **看一眼**：其中如果有第二季，告诉我，用配置指定 |

| `SUBS_IN_ARCHIVE` | 字幕在压缩包里 | `.7z`/`.rar`/`.zip` 里有字幕或字体，Jellyfin 看不到（未解压） | 10 | 先记录，按你的决定不处理 |

| `SUBS_UNPAIRED` | 字幕配不上视频 | 字幕名和任何视频主名都不匹配，或对应视频没上传 | 2 | 先记录，人工补 |
| `SUB_FORMAT_UNSUPPORTED` | 字幕格式不支持 | `.ttml` / `.dfxp` / `.lrc`，Jellyfin 不认识 | 0 | 只记录 |
| `NO_VIDEO` | 没有视频 | 条目里一个视频都没有 | 1 | 跳过（游戏安装包） |
| `NOT_MEDIA` | 不是影视内容 | 游戏安装包、exe、docx 之类 | 1 | 跳过 |

## 6. 需要你拍板的 7 件事

> 每条都给了推荐值，你只需要说「同意」或改。

**Q1. 配置格式改成 JSON 可以吗？**
服务器 Python 3.10 没有 `tomllib`、也没有 pip 装 `tomli`。
→ 推荐：`config.json`（标准库 `json`），语法和 TOML 差不多，只是没有注释。

**Q2. 多份字幕要不要映射成标准语言码？**
现实是 76 个视频都是「简体 + 繁体」两份（`.sc` / `.tc`）。
- 不映射（原决定）：两份都保留，但 Jellyfin 里语言显示「未知」，客户端不能按语言自动选；
- 映射（新建议）：`.sc → zh-CN`、`.tc → zh-TW`（或 `zh-Hant`），**字幕文件名照样唯一**，还能按语言自动选。
→ 推荐：**映射**（`chs/chi/sc/gb → zh-CN`，`cht/tc/big5 → zh-TW`），代价很小、收益很直接。

**Q3. 压缩包里的字幕怎么办？**
24 个包（主要是 `.7z`/`.rar`，服务器没有 7z 命令）。
- 方案 A：跳过，报告里提示「这部剧的字幕在 xxx.7z 里」；
- 方案 B：装 `p7zip-full`（需要 sudo 密码，约 3 MB）后自动解压字幕到视频旁；
- 方案 C：只处理 `.zip`（标准库能解），`.7z/.rar` 跳过。
→ 推荐：**先 A，装 7z 后升级到 B**（不影响主流程）。

**Q4. 那 73 个没有季号的剧，默认 S01 可以吗？**
→ 推荐：可以。报告里显式标出来，等你以后传第二季时再指定。

**Q5. Slime 第三季这种「连续编号」怎么处理？**
`[48.5-72]` + `3rd Season` → 建议自动算出偏移（49→S03E01），`.5` 集放 `Specials`。
→ 推荐：**自动算，但只在目录名里同时有季号和范围时才做**，其它情况一律报告不猜。

**Q6. 同一部剧的两套 release（Hensuki）怎么处理？**
→ 推荐：**保留一份**（分辨率高/体积大的），另一份留 upload，报告里列出「已存在另一版本」。

**Q7. 花絮/图片/OST 的归属**
- 花絮能确定宿主（在剧集目录里、命名带 `SP/PV/CM`）→ 搬到 `extras/`；
- 花絮无法确定宿主（散落在 upload 根下）→ 不动；
- 图片只认 `cover.jpg`/`folder.jpg`/`poster.jpg`，其余（189 张扫描图）不动；
- OST 不动。
→ 推荐：按上面执行。

## 7. 执行模型（已按你的选择调整）

你选择的是「**先只做预览，不执行**」，所以当前交付的就是这三步里的第 1 步：

```text
第 1 步  预览（只读）—— 已实现
         ./bin/jf-ingest preview
         → logs/<时间>-preview.md   人看的报告
         → logs/<时间>-plan.tsv     一行一个条目的确认表
         → logs/<时间>-preview.json 完整数据

第 2 步  人工过一遍确认表（待定）
         每行 = 一个条目：源目录 | 类型 | 片名 | 年份 | 季 | 集范围 | 目标 | 状态 | 待确认

第 3 步  执行（阶段二，未实现）
         ./bin/jf-ingest apply --plan logs/<时间>-plan.tsv
```

阶段一跑真实数据的产物在 `doc/inventory/real-run/`，可以直接打开看。

如果你之后想「全自动、错了再说」，可以把第 2 步做成可选；但目前不建议跳过。
